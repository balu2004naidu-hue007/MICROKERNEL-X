# MICROKERNEL-X Development Roadmap

MICROKERNEL-X is an experimental microkernel/RTOS-style project written in C,
with an ARM Cortex-M4 port. Completed items below refer to implemented
features and the tests currently performed.

## Phase 1 — Kernel Foundations

- [x] Define task states and Task Control Block
- [x] Implement task representation and initialization

## Phase 2 — Task Scheduling

- [x] Implement task selection, blocking, unblocking and delays
- [x] Add priority-aware scheduling and time-slice handling
- [x] Add ARM task context setup and context switching
- [x] Validate scheduler behaviour and context-frame boundaries
- [x] Add watchdog progress detection and recovery behaviour

## Phase 3 — Kernel Services

- [x] Implement inter-task communication (IPC)
- [x] Implement mutex synchronization and priority inheritance
- [x] Add circular-deadlock detection and recovery checks
- [x] Implement fixed-block bitmap memory pool (up to 32 blocks)
- [x] Add allocation, exhaustion, reuse, alignment and invalid-free tests
- [x] Add memory-pool critical-section callbacks
- [x] Integrate ARM SVC, PendSV and SysTick support

## Phase 4 — Testing and Reliability

- [x] Run host regression tests
- [x] Test mutex ownership, priority inheritance and deadlock handling
- [x] Test scheduler and task context-frame checks
- [x] Test watchdog, bounded recovery and task isolation
- [x] Build ARM firmware and run selected QEMU runtime checks
- [x] Automate ARM emulator regression tests with QEMU/GDB
- [x] Add a GitHub Actions workflow for host and ARM/QEMU tests
- [ ] Expand stress, long-duration and fault-injection testing
- [ ] Verify the CI workflow on its first remote run

## Phase 5 — Embedded Integration

- [x] Implement the ARM Cortex-M4 firmware demonstration port
- [x] Build the ARM ELF firmware and binary image
- [x] Perform selected runtime checks in QEMU
- [ ] Validate startup, timing, interrupts and recovery on physical Cortex-M hardware

## Phase 6 — Developer and Recruiter Presentation

- [x] Document current features, build commands and known limitations
- [x] Add a host-side dashboard demo that calls the kernel C APIs
- [x] Export chronological trace events and task snapshots as JSON
- [x] Add a static dashboard for task states, scheduler, mutex, IPC, recovery and memory pool
- [x] Add a GitHub Pages deployment workflow
- [ ] Verify the first remote Pages deployment
- [ ] Publish the project source and dashboard to GitHub

## Current Status

The core scheduler, synchronization, recovery checks, IPC, tracing, fixed-block
memory pool and ARM Cortex-M4 demonstration port have been implemented. The
host regression suite and selected ARM/QEMU runtime checks passed locally.

The visual dashboard is generated by `dashboard_demo.c` through the actual
kernel C modules. It presents a deterministic host scenario in a browser; it
is not live hardware telemetry. Physical-board validation, broader stress
testing and the first remote CI/Pages runs remain outstanding.
